| `net-liquidity` | `BIS_GLOBAL_LIQUIDITY_USD_BN` | `ingest-nyfed-markets` | `public.vw_net_liquidity` | `daily` | `USD bn` | `FRED WALCL`, `FRED WTREGEN`, `FRED RRPONTSYD`, `NY Fed H.4.1` | The terminal reads `public.vw_net_liquidity` directly. `ingest-nyfed-markets` writes the TGA and ON RRP legs into `metric_observations`, the Fed balance-sheet leg comes from the FRED ingestion path, and downstream digest code still refers to the mirror id `BIS_GLOBAL_LIQUIDITY_USD_BN`. ## Concerns

- `public.vw_net_liquidity` is consumed across the repo, yet its SQL definition is not present in the checked-in migrations I could inspect.
- `BIS_GLOBAL_LIQUIDITY_USD_BN` remains in frontend and digest registries while `20260801000002_deactivate_unsourced_metrics.sql` explicitly deactivates it.
- `sovereign-stress-index` has a public methodology contract, yet the repo has no checked-in producer or migration that writes `BOP_VULNERABILITY_SCORE`.
- `ingest-cofer` currently uses simulated quarterly rows in checked-in code. The mapping reflects the current producer path, and the source quality issue is called out in the task report.
